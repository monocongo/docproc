# Planning documents

This directory contains time-bounded implementation plans and project proposals that have not yet become durable architectural decisions.

- Keep one plan per descriptive Markdown file.
- Record implementation status near the top of each plan.
- Move lasting technical decisions into `docs/adr/` as they are accepted.
- Keep benchmark methodology and measured results in their own documentation and report directories once implemented.
- Update a plan with links to resulting ADRs, issues, or releases rather than silently rewriting its original goals.
